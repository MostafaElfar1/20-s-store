# 20's — Smell Like Your Twenties

متجر عطور صغير بتصميم فاخر (أسود وذهبي). الموقع React + Vite على **GitHub Pages**، والباك إند كله على **Supabase** (قاعدة بيانات، تسجيل دخول، صور). مفيش سيرفر خاص بيك، ومفيش أي حاجة مدفوعة.

## إيه اللي جوه المشروع

```
.github/workflows/deploy.yml   النشر التلقائي على GitHub Pages
scripts/check-public-key.sh    بيمنع نشر الموقع لو حطيت مفتاح سري بالغلط
supabase/migrations/           ملفات SQL (بتتشغل بالترتيب)
supabase/sample_product.sql    منتج تجريبي للاختبار فقط
src/lib/                       الإعدادات، Supabase، الواتساب، التحقق من البيانات
src/context/                   الكارت، تسجيل الدخول، الإشعارات
src/pages/                     صفحات المتجر
src/pages/admin/               صفحات لوحة الأدمن
src/components/                مكونات قابلة لإعادة الاستخدام
```

## اللي الموقع بيعمله

- **المتجر**: صفحة رئيسية، كتالوج (بحث، تصنيف، ترتيب، Featured، Load more)، تفاصيل المنتج، كارت بيتحفظ في المتصفح، وCheckout كاش عند الاستلام.
- **الأوردر**: بيتحفظ في Supabase عن طريق دالة `create_order` (الأسعار والمخزون بتتحسب في الداتابيز، مش من المتصفح). بعد الحفظ بيظهر زرار واتساب فيه تفاصيل الأوردر.
- **الأدمن** على `/#/admin`: تسجيل دخول، إحصائيات، إدارة المنتجات مع رفع الصور، وإدارة الأوردرات وتغيير حالتها.

2. حساب **Supabase**: supabase.com
3. على جهازك: **Node.js** (نسخة LTS 20 أو أحدث) و**Git**.

```bash
node -v
git --version
```

## 2) إنشاء مشروع Supabase

1. من الداشبورد: **New project**.
2. الاسم `20s-store`، وحط **Database Password** قوي واحفظه (مش هتحطه في الموقع أبدًا).
3. اختار Region قريبة، واضغط Create وانتظر لحد ما يجهز.

## 3) إنشاء الجداول والدوال

من **SQL Editor** ثم **New query**، الصق كل ملف من `supabase/migrations` واضغط **Run**، **بالترتيب ده بالظبط**:

| الملف | بيعمل إيه |
|---|---|
| `001_schema.sql` | الجداول `products` و`orders` و`order_items` و`admins` + القيود والـ indexes |
| `002_rls.sql` | دالة `is_admin()` وسياسات الأمان (RLS) |
| `003_create_order.sql` | دالة إنشاء الأوردر (atomic + منع التكرار) |
| `004_storage.sql` | bucket الصور `product-images` وسياساته |
| `005_order_status_transitions.sql` | بيمنع تغيير حالة الأوردر بشكل غير مسموح |
| `006_restock_on_cancel.sql` | بيرجّع المخزون مرة واحدة عند إلغاء الأوردر |

لو بتعدّل ملف وتعيد تشغيله: كلهم آمنين لإعادة التشغيل ما عدا `001` (هيعمل error لأن الجداول موجودة، وده عادي).

لو ظهر خطأ `Could not find the function create_order` بعد التشغيل، شغّل:

```sql
notify pgrst, 'reload schema';
```

## 4) سياسات الأمان (RLS)

اتعملت جوه `002_rls.sql` وـ`004_storage.sql`، مش محتاج تعمل حاجة يدوي. الخلاصة:

- الزائر بيقرأ المنتجات **النشطة** بس.
- الزائر **مبيقراش** أي أوردر أو بيانات عملاء، ومبيقدرش يكتب في أي جدول مباشرة.
- إنشاء الأوردر بيتم **فقط** عن طريق `create_order`.
- الأدمن (اللي في جدول `admins`) بس يقدر يدير المنتجات والصور، وبيغيّر **حالة** الأوردر بس (مش بيانات العميل).
- Bucket الصور بيتقري للعامة، والرفع والتعديل والحذف للأدمن بس.

## 5) Bucket الصور

`004_storage.sql` بيعمله لوحده: اسمه `product-images`، عام للقراءة، بحد 3 ميجا، وJPEG/PNG/WebP بس. للتأكد: **Storage** من القائمة، لازم تلاقيه موجود.

لو غيّرت حد الحجم، غيّره في مكانين: الـ bucket، وثابت `MAX_IMAGE_MB` في `src/lib/admin.js`.

## 6) إنشاء أول أدمن (بأمان)

مفيش صفحة تسجيل عامة في الموقع. الأدمن بيتعمل كده:

1. **Authentication** ثم **Users** ثم **Add user** ثم **Create new user**، اكتب إيميلك وباسورد قوي، وفعّل **Auto Confirm User**.
2. انسخ الـ **UID** بتاعه.
3. في **SQL Editor** شغّل:

```sql
insert into admins (user_id) values ('الـ-UID-هنا');
```

4. (مُوصى بيه) من **Authentication** ثم **Sign In / Providers**، عطّل **Allow new users to sign up**.

الصلاحية بتتحدد بوجود اليوزر في جدول `admins` والداتابيز بتتحقق منها في كل طلب. الباسورد مبيتخزنش في الكود ولا في المتصفح.

## 7) متغيرات البيئة (Environment variables)

انسخ `.env.example` لملف اسمه `.env` (الملف ده متجاهَل في Git، متحطوش في GitHub أبدًا):

```
VITE_SUPABASE_URL=       من Project Settings > API > Project URL
VITE_SUPABASE_PUBLISHABLE_KEY=   المفتاح anon / publishable
VITE_STORE_NAME=20's
VITE_STORE_SLOGAN=Smell Like Your Twenties
VITE_WHATSAPP_NUMBER=201055983906
VITE_INSTAGRAM_URL=      اختياري
VITE_FACEBOOK_URL=       اختياري
```

**الفرق بين العام والسري:**

- كل متغير بيبدأ بـ `VITE_` **بيتحط جوه كود الموقع** وأي حد يقدر يشوفه. فده للقيم **العامة** بس: رابط المشروع والمفتاح العام (anon / publishable) واسم المتجر ورقم الواتساب.
- الأمان بييجي من سياسات RLS في الداتابيز، مش من إخفاء المفتاح العام.
- **سري ومرفوض تحطه في الموقع أو GitHub:** مفتاح `service_role` أو `sb_secret_...` وباسورد الداتابيز. الـ workflow فيه فحص بيوقّف النشر لو حطيت مفتاح سري بالغلط.

## 9) اختبار دورة الأوردر كاملة

1. شغّل `supabase/sample_product.sql` (منتج تجريبي)، أو أضف منتج من الأدمن.
2. افتح الموقع، ضيف المنتج للكارت، وأعد تحميل الصفحة (الكارت لازم يفضل).
3. اعمل Checkout بموبايل مصري صحيح. لازم تظهر "Order saved" ورقم زي `20S-1001`.
4. اضغط زرار الواتساب، لازم تفتح محادثة مع رقم المتجر والرسالة جاهزة. (لازم تضغط Send جوه واتساب بنفسك.)
5. في Supabase **Table Editor**: الأوردر في `orders` والمخزون نقص في `products`.
6. في `/#/admin`: الأوردر ظاهر، غيّر حالته، وجرّب إلغاءه وتأكد إن المخزون رجع.
7. افتح `/#/admin` من نافذة Incognito من غير تسجيل دخول، لازم يحوّلك لصفحة الدخول.

## 10) إنشاء مستودع GitHub

1. github.com ثم **New repository**، اسمه مثلًا `20s-store`.
2. خليه **Public**. (على الخطة المجانية GitHub Pages بيشتغل مع المستودعات العامة. ومفيش أي سر في الكود، فده آمن.)
3. متضيفش README أو .gitignore من عندهم لأنهم موجودين.

## 11) رفع الكود

من فولدر المشروع (غيّر `USERNAME` و`REPO`):

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git

```

قبل ما تعمل `git add` تأكد إن `git status` مش بيعرض `.env`.

## 12) النشر على GitHub Pages

1. في المستودع: **Settings** ثم **Pages** ثم **Source** اختار **GitHub Actions**.
2. **Settings** ثم **Secrets and variables** ثم **Actions** ثم تاب **Variables** ثم **New repository variable**. ضيف:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
   - `VITE_STORE_NAME`
   - `VITE_STORE_SLOGAN`
   - `VITE_WHATSAPP_NUMBER`
   - (اختياري) `VITE_INSTAGRAM_URL` و`VITE_FACEBOOK_URL`

   ملف `.env` بتاعك **مش** بيروح لـ GitHub، فلازم تحط القيم دي هنا بنفسك.
3. اعمل push (أو من تاب **Actions** ثم **Deploy to GitHub Pages** ثم **Run workflow**).
4. بعد ما ينجح، الموقع على: `https://USERNAME.github.io/REPO/` والأدمن على `https://USERNAME.github.io/REPO/#/admin`.

أي تعديل بعد كده: `git add . && git commit -m "..." && git push` والنشر بيتم لوحده.

الموقع بيستخدم **hash routing** (`/#/...`) وروابط ملفات نسبية، فبيشتغل تحت مسار المستودع وبعد الـ Refresh من غير إعدادات إضافية.

## 13) تغيير اسم المتجر ورقم الواتساب

غيّر `VITE_STORE_NAME` و`VITE_WHATSAPP_NUMBER` في `.env` (محليًا) وفي **Variables** في GitHub (للموقع المنشور)، وبعدها أعد النشر.

**تحويل رقم الموبايل المصري للصيغة الدولية:** شيل الصفر الأول وحط `20` قبله. أرقام فقط، من غير `+` ولا مسافات.

```
01055983906  ->  201055983906
```

لو الرقم مش متظبط، زرار الواتساب بيتقفل وبتظهر رسالة بتقولك تظبطه.

## 14) حل المشاكل الشائعة

| المشكلة | الحل |
|---|---|
| الموقع المنشور فاضي أو "not connected to Supabase" | الـ Variables ناقصة في GitHub. ضيفها وأعد تشغيل الـ workflow. |
| الـ workflow وقف عند فحص المفتاح | حطيت مفتاح سري. استخدم الـ anon / publishable. |
| "Not authorized" في الأدمن | اليوزر مش في جدول `admins`. راجع الخطوة 6. |
| المنتجات مش بتظهر في المتجر | تأكد إن `is_active` = true، وإن `002_rls.sql` اتشغّل. |
| فشل رفع الصورة | تأكد إنك أدمن، وإن `004_storage.sql` اتشغّل، وإن الصورة JPEG/PNG/WebP وأقل من 3 ميجا. |
| الصور مش بتظهر | الـ bucket لازم يكون Public. شغّل `004_storage.sql` تاني. |
| `Could not find the function create_order` | شغّل `003_create_order.sql` ثم `notify pgrst, 'reload schema';` |
| `INVALID_STATUS_TRANSITION` | انتقال حالة مش مسموح (مثلًا من pending لـ delivered). ده متصمم كده. |
| الموقع بطيء أول مرة أو مفيش اتصال | مشروع Supabase المجاني بيتوقف لو مفيش نشاط. افتحه من الداشبورد (Restore). |
| تعديل الـ SQL مش باين | شغّل الملف المعدّل من SQL Editor، الداتابيز مش بتتحدث لوحدها من الملفات. |

## 15) حدود الخطة المجانية وتكاليف محتملة

الأرقام دي من مصادر منشورة في 2026 وبتتغير، **راجع supabase.com/pricing** قبل الاعتماد عليها:

- Supabase المجاني: حوالي 500 ميجا قاعدة بيانات، مساحة تخزين صور محدودة، وحد لنقل البيانات الشهري، ومشروعين نشطين.
- **المشروع المجاني بيتوقف (pause) بعد أسبوع من عدم النشاط.** لو المتجر هادي، دخّل عليه مرة في الأسبوع على الأقل، أو فكّر في خطة مدفوعة لو بتعتمد عليه بجد.
- GitHub Pages: مجاني للمستودعات العامة، مع حدود استخدام معقولة للمواقع الصغيرة.

**ميزات مستقبلية ممكن تكلّف:** دفع أونلاين (رسوم بوابة الدفع)، إرسال رسائل واتساب تلقائية (WhatsApp Business API مدفوع)، إرسال إيميلات، دومين خاص، وخطة Supabase Pro لو كبرت.

## حدود معروفة (مكتوبة بصراحة)

- **صورة واحدة** لكل منتج.
- **مفيش حماية من الأوردرات الوهمية بالجملة**: أي حد يقدر يستدعي `create_order` (ده لازم عشان العميل يطلب من غير حساب). الدالة بتتحقق من البيانات والمخزون، لكن مفيش CAPTCHA أو rate limit. لو حصل إزعاج، الخطوة الجاية CAPTCHA (زي Cloudflare Turnstile) أو Edge Function.
- **الواتساب**: فتح المحادثة لا يثبت إن الرسالة اتبعتت. الأوردر محفوظ في الداتابيز بغض النظر. مفيش إرسال تلقائي.
- **مفيش إيميلات** ولا إشعارات للأدمن عند وصول أوردر جديد. لازم تفتح لوحة الأدمن.
- الكارت محفوظ في المتصفح بس (مش بين الأجهزة).
- الإلغاء بيرجّع المخزون مرة واحدة. الأوردرات اللي اتلغت قبل `006` مخزونها لازم يتظبط يدويًا.
- حذف المنتج نهائي. الأوردرات القديمة بتفضل بأسماء وأسعار المنتجات وقت الشراء.

## اللي اتجرّب فعلًا واللي لأ

**اتجرّب (أثناء بناء المشروع):**
- `npm run build` ينجح، والـ `index.html` فيه روابط ملفات نسبية، والملفات بتتحمّل (200) لما اتقدّمت تحت مسار فرعي `/my-repo/` بسيرفر ثابت.
- ملفات الـ SQL (001 و002 و003 و005 و006) على Postgres 16 محلي مع محاكاة أدوار Supabase: حساب السعر والمخزون، منع التكرار، رفض البيانات الغلط، RLS للزائر ولليوزر العادي، انتقالات الحالة، الاسترجاع مرة واحدة، حفظ سطور الأوردر بعد حذف المنتج، و6 أوردرات متزامنة على آخر قطعة (نجح واحد فقط).
- دوال التحقق من التليفون وبناء رابط واتساب وتحويل الأرقام.
- فحص المفتاح: بيرفض `sb_secret_` وJWT بدور `service_role`، ويقبل المفتاح العام.
- الـ bundle المبني مفيهوش `service_role`. (النص `sb_secret_` الموجود فيه جزء من كود مكتبة Supabase نفسها اللي بتفحص نوع المفتاح، مش مفتاح.)
- المالك أكّد إن المتجر والأوردر والواتساب ولوحة الأدمن (تسجيل الدخول والمنتجات والأوردرات) اشتغلت على جهازه مع مشروع Supabase الحقيقي.

**ما اتجرّبش:**
- تشغيل الـ workflow فعليًا على GitHub، والموقع المنشور على `github.io`.
- `004_storage.sql` وسياسات الـ Storage على Supabase حقيقي بشكل آلي.
- اختبارات أوتوماتيك للواجهة، والشكل على موبايلات حقيقية، وإمكانية الوصول (accessibility) بأدوات.
- رسالة واتساب وصلت فعلًا لصاحب المتجر (مش ممكن التحقق منها تقنيًا).
